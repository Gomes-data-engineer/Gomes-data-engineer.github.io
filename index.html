Evollo · Analytics Engineer Dec 2022 – Sep 2026

The data lake behind a conversation-analytics platform

Problem

Client data arrived from many places and in many shapes, some of it uploaded by hand. The product needed clean metadata linked to the right audio, PDF and text files to replay each conversation — and the Power BI models on top were heavy (336 MB, 20-minute refreshes).

Approach

  • Extraction with Python and Pentaho from SFTP, REST APIs and CRMs, other S3 buckets, SharePoint/OneDrive and relational and NoSQL databases (MySQL, PostgreSQL, SQL Server, MongoDB) — pagination, retries, CloudWatch logs.
  • Landed raw data in the S3 data lake, mostly as JSON, next to the conversation files: audio, PDFs, text, CSV/XLSX and TAR/ZIP archives. Some flows went straight to the database.
  • A three-step Python flow: validation (Unity, a metadata & quality engine with alerts) → treatment → delivery to the company platform, which used the metadata and file path to find and play back each conversation.
  • Table-driven orchestration with AWS Lambda and Terraform, replacing manual client uploads.
  • On the BI side, moved heavy logic upstream into SQL (star schema, query folding, leaner DAX); business workflows automated with Power Automate.

CPP Digital · Data Engineer Jun 2026 – Dec 2026

Starting a data practice from zero

Problem

As the company's only data professional, I found HR, QA and operations asking real questions — but the data lived in Notion, GitLab, Slack, SharePoint and timesheets, with no warehouse, no history and no standards.

Approach

  • Built the warehouse: PostgreSQL + dbt Core + Python + Docker + GitLab, Bronze / Silver / Gold, ~30 custom SQL tests.
  • Ingested the Notion API (HR evaluation cycles), the GitLab API (merge requests, merges, failed pipelines — metrics for the QA team), the Slack API and SharePoint files.
  • Shipped five data products: the Individual Development Plan with a People Health Index and promotion-eligibility logic, Workforce analytics, QA Maturity, a people directory and an AI Usage study.
  • AI Usage: who uses Claude Code, how much, and for which client — prorated by timesheet hours — so the company could see how much to charge to cover AI costs.
  • Wrote 7 Claude Code skills (scaffold, KPI advisor, pipeline, theme, design, QA, documentation) so anyone gets the same structure and checks; BI standards, PBIP/TMDL in Git, GDPR/LGPD rules (aggregates only, small groups suppressed).

02 · Data visualization

Dashboards that explain, not decorate.

A beautiful dashboard nobody understands is a failed one. I design reports like products: start from the decision, keep only what helps it, and design in Figma before a single visual goes into Power BI.

01

Question first

Every page answers a decision. KPIs, targets and baselines are agreed with the stakeholder before design starts.

02

Only what's needed

Remove what doesn't carry meaning: borders, legends, decimals, extra colors. Color is used to point, not to paint.

03

Designed in Figma

Wireframes and mocks first, then backgrounds, themes and a component library — light and dark — built on a design system.

04

Fast by design

Star schema, lean DAX and logic upstream in SQL, so the report answers in seconds, not minutes.
