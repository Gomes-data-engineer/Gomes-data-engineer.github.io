Evollo · Analytics Engineer dez 2022 – set 2026

O pipeline de dados por trás de uma plataforma de speech analytics

Problema

Grandes bancos, operadoras de telecom, varejistas e seguradoras brasileiros enviavam metadados de interações e gravações de chamadas em todo tipo de formato, muitas vezes à mão. A plataforma de speech analytics precisava desses dados validados e ligados às gravações certas antes da transcrição, com prazo diário, e os modelos de Power BI em cima disso eram pesados (336 MB, atualização de 20 minutos).

Abordagem: um pipeline de seis etapas por cliente

  1. Captura: metadados e arquivos de APIs dinâmicas e CRMs, SFTP, S3, SharePoint/OneDrive e bancos SQL/NoSQL (MySQL, PostgreSQL, SQL Server, MongoDB), em CSV, JSON, XML, compactados e mídias, com Python e Pentaho.
  2. Padronização: os arquivos brutos vão para o AWS S3 e viram arquivos tabulares datados (YYYYMMDD_metadados.csv).
  3. Portão de qualidade: checagem automática de colunas, tipos de dados, separadores e codificação. O que é válido entra no data warehouse; o que é inválido dispara um e-mail automático ao cliente dizendo exatamente o que corrigir e reenviar.
  4. Seleção e validação de mídia: regras de negócio de cada cliente no warehouse escolhem as interações a analisar; o cliente sobe as gravações correspondentes em cerca de um dia, e uma rotina à meia-noite valida nome, tamanho e integridade dos arquivos, alertando sobre falhas.
  5. Speech analytics: as mídias validadas passam por transcrição (fala → texto) e marcação com IA de termos e categorias, e seguem para a plataforma de qualidade.
  6. Entrega: Power BI embarcado na plataforma, além de arquivos de retorno customizados, com transcrições e marcações, para os sistemas internos de cada cliente.

Por baixo dos panos

  • Orquestração orientada a tabela com AWS Lambda e Terraform, logs no CloudWatch e o Unity, um motor Python de metadados e qualidade com alertas, substituindo os uploads manuais dos clientes.
  • No BI, levei a lógica pesada para o SQL (esquema estrela, query folding, DAX mais enxuto); fluxos de negócio automatizados com Power Automate.

CPP Digital · Data Engineer jun 2026 – dez 2026

Criando uma área de dados do zero

Problema

Como único profissional de dados da empresa, encontrei RH, QA e operações com perguntas reais, mas os dados estavam espalhados entre Notion, GitLab, Slack, SharePoint e timesheets, sem warehouse, sem histórico e sem padrões.

Abordagem

  • Construí o warehouse: PostgreSQL + dbt Core + Python + Docker + GitLab, camadas Bronze / Silver / Gold, ~30 testes SQL customizados.
  • Ingestão da API do Notion (ciclos de avaliação do RH), da API do GitLab (merge requests, merges, pipelines que falharam: métricas para o time de QA), da API do Slack e de arquivos no SharePoint.
  • Entreguei cinco produtos de dados: o Plano de Desenvolvimento Individual (IDP) com People Health Index e regras de elegibilidade a promoção, Workforce analytics, QA Maturity, um diretório de pessoas e um estudo de uso de IA.
  • Uso de IA: quem usa Claude Code, quanto e para qual cliente, rateado pelas horas do timesheet, para a empresa saber quanto cobrar para cobrir o custo de IA.
  • Escrevi 7 skills de Claude Code (scaffold, KPIs, pipeline, tema, design, QA, documentação) para que qualquer pessoa obtenha a mesma estrutura e os mesmos checks; padrões de BI, PBIP/TMDL no Git, regras de GDPR/LGPD (só agregados, grupos pequenos suprimidos).

02 · Visualização de dados

Dashboards que explicam, não que enfeitam.

Um dashboard bonito que ninguém entende é um dashboard que falhou. Desenho relatórios como produto: começo pela decisão, mantenho só o que ajuda nela e desenho no Figma antes de qualquer visual entrar no Power BI.

01

A pergunta vem primeiro

Cada página responde a uma decisão. KPIs, metas e bases de comparação são combinados com quem pede antes do design começar.

02

Só o necessário

Tiro o que não carrega significado: bordas, legendas, casas decimais, cores extras. Cor serve para apontar, não para pintar.

03

Desenhado no Figma

Wireframes e mocks primeiro; depois fundos, temas e uma biblioteca de componentes, claro e escuro, sobre um design system.

04

Rápido por design

Esquema estrela, DAX enxuto e lógica no SQL, para o relatório responder em segundos, não em minutos.

  1. Briefing
  2. KPIs
  3. Wireframe · Figma
  4. Tema e componentes
  5. Build · Power BI
  6. QA e teste com usuário
